# municipal-opendata-kit

市町村が公開しているオープンデータ（AED・避難場所・公共施設・文化財・観光など）を、デジタル庁の「[自治体標準オープンデータセット](https://www.digital.go.jp/resources/open_data/municipal-standard-data-set-test)」の形式に整え、位置（緯度・経度）を付けるためのキットです。

埼玉県草加市のデータ（5種類・410件）を手作業で整えた経験を「型」にしたもので、越谷市・川口市・さいたま市にも適用しています（下の「4市での結果」）。**市を追加するときの作業を、設定ファイル1つと、AIによる確認作業までに減らす**ことを目指しています。

## できること

| 工程 | 内容 |
| --- | --- |
| 取得 | 元データ（CSV / Excel、UTF-8 / Shift_JIS）を読む。県の一覧から1市分を抜き出すことも可 |
| 対応づけ | 元の列名を標準の項目名に対応づける（設定ファイル）。複数の列の差し込み、備考への退避も可 |
| 整形 | 和暦→西暦、度分秒→10進数、全角→半角（住所・電話番号だけ）、住所を町字／番地以下／建物名等に分割 |
| 町字 | デジタル庁「アドレス・ベース・レジストリ」の町字マスターと照らし、丁目を省いた住所（「青木2-1-1」）を「青木2丁目」「1-1」に分け、町字IDを付ける |
| 位置の付与 | ①元データの座標 → ②公共施設情報の同名施設から転記 → ③国土地理院「住所検索API」の順。どれで付けたかを備考に記録 |
| 表記の修正 | すでに標準形式のデータでも、Excelの日付シリアル値・時刻の小数、指数表記で壊れた法人番号、市区町村欄への住所全体の混入、全角半角のゆれ、日付・時刻・電話番号の書き方、以前の版の列名、名称のない行などを直し、記録を残す |
| 検証 | 市の範囲外の座標、資料間の住所の食い違いを検出。市が市外に持つ施設（臨海学園など）は範囲チェックの対象外として一覧にする |
| 出力 | 標準形式の CSV（UTF-8 BOM付き・CRLF）と、出典・加工内容・精度の内訳を書いた README |

## 人の判断が要るところは AI（Claude Code）が一次判断する

型にしても、次の判断は機械的には決まりません。ここを Claude Code のスキルが担当し、根拠付きの判断を `decisions.json` に残します。

| 判断 | 例 | AI がすること |
| --- | --- | --- |
| 施設名の照合 | 「草加市役所西棟１階」は公共施設情報の「市役所」と同じか | 住所と名前から判断し、同じなら座標を転記 |
| 住所の分割 | 「柿木町地内」 | 町字・番地以下・建物名等に分ける |
| 位置の付け直し | 番地まで特定できなかった住所 | 表記ゆれを直して再検索、または同じ施設を指定 |
| 資料間の食い違い | 同じ図書館なのに番地が違う | どちらを採るか決め、市への確認事項として記録 |

AI の判断は**必ずコードで検証**してから使います。

- 座標は AI に作らせない（元データ・公共施設情報・国土地理院の結果からのみ）
- 候補にない施設名を選んだ判断、つなげても元の住所に戻らない分割は採用しない
- AI が迷ったものは `needs_human` として人に回す

## 使い方

Python 3.11 以上が必要です（Excel を読むときだけ `pip install openpyxl`）。

```bash
# 1. 元データを置く（設定ファイルの source が URL なら fetch で取得。町字マスターも取得する）
python -m odkit fetch cities/soka.toml

# 2. 標準形式に整える
python -m odkit build cities/soka.toml

# 3. 確認待ちが出たら、Claude Code でこのリポジトリを開いて
/odkit-review

# 4. もう一度 build（判断が反映され、確認待ちが減る）
python -m odkit build cities/soka.toml
```

出力は `output/<市>/`、作業ファイル（住所検索のキャッシュ・確認リスト・判断記録）は `work/<市>/` にできます。

### 新しい市を追加する

Claude Code でこのリポジトリを開き、`/odkit-add-city 〇〇市` と頼むと、下の 1〜4 を AI が通しで進めます（人の確認が要るものだけが残ります）。ほかのコーディングエージェントに任せるときは [docs/prompt.md](docs/prompt.md) のプロンプトを使えます。

手で進める場合：


1. 埼玉県内の市町村なら、県のオープンデータポータルから候補を自動で探せる
   ```bash
   python -m odkit discover 川口市 --slug kawaguchi
   ```
   標準データセットに当たりそうなデータとダウンロード先を調べ、`cities/<slug>.draft.toml`（設定の下書き）を作る。
   県外の市町村は `cities/soka.toml` を写して `cities/<市>.toml` を作り、元データを `sources/<市>/` に置く
2. `python -m odkit fetch cities/<市>.toml` で元データを取得する
3. Claude Code で `/odkit-map-columns` を実行し、列の対応づけを下書きしてもらう（`python -m odkit inspect` の結果を使う）
4. 内容を確認して `build` → `/odkit-review` → `build`

| 市 | 設定ファイル | 元データの状態 |
| --- | --- | --- |
| 埼玉県草加市 | `cities/soka.toml` | 独自形式。AED・避難場所に位置なし |
| 埼玉県越谷市 | `cities/koshigaya.toml` | 多くは標準形式だが表記の崩れあり。AED は施設名だけ（住所・位置なし） |
| 埼玉県川口市 | `cities/kawaguchi.toml` | 5種類とも標準形式（市のサイトで公開）。住所は丁目を省いた形、公共施設一覧に位置なし、市外の施設あり |
| 埼玉県さいたま市 | `cities/saitama.toml` | 政令指定都市（区ごとの団体コード・町字マスター）。AED・避難場所は独自形式、文化財は市所有分のみ CSV、観光施設なし |

## 4市での結果（2026年10月30日）

埼玉県の隣り合う4市（草加市・越谷市・川口市・さいたま市）のデータを、同じキットで整えた結果です。対象は AED・指定緊急避難場所・公共施設・文化財・観光施設の5種類。

| | 草加市 | 越谷市 | 川口市 | さいたま市 |
| --- | --- | --- | --- | --- |
| 元データの公開場所 | 県ポータル | 県ポータル | 市のサイト（県ポータルはリンクのみ） | 県ポータル |
| 元データの形式 | 独自形式 | ほぼ標準形式 | 標準形式 | 公共施設は標準形式、AED・避難場所・文化財は独自形式 |
| 件数 | 410 | 544 | 1,823 | 1,908 |
| 元データで位置あり | 245 | 433 | 661 | 1,906 |
| キットで付けた位置 | 165 | 105 | 1,158 | 0 |
| 　うち住所検索（番地・街区） | 45 | 0 | 1,043 | 0 |
| 　うち公共施設情報から転記 | 111 | 72 | 27 | 0 |
| 　うち町字の代表点（要確認） | 9 | 33 | 88 | 0 |
| 位置を付けられなかった | 0 | 6 | 4 | 2 |
| 表記を直した箇所 | — | 927 | 2,267 | 1,024 |
| AI の判断を採用 | — | 42 | 107 | 1 |
| 人の確認待ち | — | 5 | 8 | 6 |
| 町字ID を付けた件数 | — | 437 | 1,794 | 1,887 |

- 草加市は手作業で整えた結果（このキットはその手順を型にしたもの。テストで再現を確認）。他の3市はキットで整えた結果
- 「位置を付けられなかった」は、住所も位置もない施設、無形の文化財、市外の施設で元データに位置がないもの

### 市ごとの元データの特徴（市へのフィードバックの材料）

| 市 | 特徴 |
| --- | --- |
| 草加市 | 独自形式。AED・避難場所に位置がない。文化財の座標が度分秒 |
| 越谷市 | AED が施設名だけ（住所・位置なし）。法人番号が Excel の指数表記で全件壊れている。市区町村の欄に住所全体。日付・時刻が Excel の数値のまま |
| 川口市 | 公共施設1,101件に位置がない。法人番号の破損と市区町村の欄への住所の混入（越谷市と同じ）。住所は丁目を省いた形。県ポータルの更新日が2020年のまま。観光施設1件の緯度に誤り |
| さいたま市 | 位置はほぼ全件あり。AED・避難場所・文化財は独自形式で、AED だけライセンスが CC BY。文化財の CSV は市所有分のみ（全件は PDF）。観光施設はポータルに見当たらない |

### 4市で分かったこと

- **同じ崩れが市をまたいで出る。** 法人番号の指数表記、市区町村の欄への住所の混入は越谷市・川口市の両方にあった。標準形式の雛形を Excel で編集して保存したときに起きるとみられ、作成手順の段階で防げる
- **位置の有無は市によって大きく違う。** さいたま市はほぼ全件にあり、川口市の公共施設や草加市の AED にはない。住所検索と公共施設情報からの転記で、4市とも98%以上に位置が付いた（越谷市 538/544、川口市 1,819/1,823、さいたま市 1,906/1,908、草加市 410/410）
- **住所は町字マスターと照らす必要がある。** 丁目を省いた書き方、丁目のある区域とない区域が混在する町、大字の有無の揺れ、政令指定都市の区は、住所の形だけでは決まらない。アドレス・ベース・レジストリの町字マスターと照らすことで、ほぼ自動で分けられ、町字ID も付く
- **人の判断が要るものは、市ごとに数件まで減った。** 残るのは、住所も位置もない施設、複数の町にまたがる区域、町字マスターにない町名など、市に確認するしかないもの

## テスト

```bash
python -m unittest discover tests
```

`tests/fixtures/soka/` の草加市のデータ（元データの形式に戻したもの）で、手作業の結果（AED は公共施設からの転記 79件・住所検索 29件）が再現されること、AI の判断が検証されたうえで反映されることを確かめています。

## 現時点の課題

- 町字マスターを取得していない場合、住所の分割は正規表現による簡易なもの（丁目を省いた住所を正しく分けられない）
- 住居表示の街区・住居（アドレス・ベース・レジストリの街区マスターなど）までは照らしていない
- 国土地理院の住所検索は精度の目安を返さないため、番地・街区・町字の判定は返ってきた地名との比較による推定
- 元データの更新に追従する仕組み（差分の検出・定期実行）は未実装
- BODIK などへの登録は手作業（このキットの範囲外）

詳しくは [docs/design.md](docs/design.md) を参照してください。
