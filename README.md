# municipal-opendata-kit

市町村が公開しているオープンデータ（AED・避難場所・公共施設・文化財・観光など）を、デジタル庁の「[自治体標準オープンデータセット](https://www.digital.go.jp/resources/open_data/municipal-standard-data-set-test)」の形式に整え、位置（緯度・経度）を付けるためのキットです。

埼玉県草加市のデータ（5種類・410件）を手作業で整えた経験を「型」にしたもので、**市を追加するときの作業を、設定ファイル1つと、AIによる確認作業までに減らす**ことを目指しています。

## できること

| 工程 | 内容 |
| --- | --- |
| 取得 | 元データ（CSV / Excel、UTF-8 / Shift_JIS）を読む。県の一覧から1市分を抜き出すことも可 |
| 対応づけ | 元の列名を標準の項目名に対応づける（設定ファイル）。複数の列の差し込み、備考への退避も可 |
| 整形 | 和暦→西暦、度分秒→10進数、全角→半角（住所・電話番号だけ）、住所を町字／番地以下／建物名等に分割 |
| 位置の付与 | ①元データの座標 → ②公共施設情報の同名施設から転記 → ③国土地理院「住所検索API」の順。どれで付けたかを備考に記録 |
| 検証 | 市の範囲外の座標、資料間の住所の食い違いを検出 |
| 出力 | 標準形式の CSV（UTF-8 BOM付き・CRLF）と、出典・加工内容・精度の内訳を書いた README |

## 人の判断が要るところは AI（Claude Code）が一次判断する

型にしても、次の判断は機械的には決まりません。ここを Claude Code のスキルが担当し、根拠付きの判断を `decisions.json` に残します。

| 判断 | 例 | AI がすること |
| --- | --- | --- |
| 施設名の照合 | 「草加市役所西棟１階」は公共施設情報の「市役所」と同じか | 住所と名前から判断し、同じなら座標を転記 |
| 住所の分割 | 「柿木町地内」 | 町字・番地以下・建物名等に分ける |
| 位置の付け直し | 番地まで特定できなかった住所 | 表記ゆれを直して再検索、または同じ施設を指定 |
| 資料間の食い違い | 同じ図書館なのに番地が違う | どちらを採るか決め、市への確認事項として記録 |

AI の判断は**必ずコードで検証**してから使います。

- 座標は AI に作らせない（元データ・公共施設情報・国土地理院の結果からのみ）
- 候補にない施設名を選んだ判断、つなげても元の住所に戻らない分割は採用しない
- AI が迷ったものは `needs_human` として人に回す

## 使い方

Python 3.11 以上が必要です（Excel を読むときだけ `pip install openpyxl`）。

```bash
# 1. 元データを置く（設定ファイルの source が URL なら fetch で取得）
python -m odkit fetch cities/soka.toml

# 2. 標準形式に整える
python -m odkit build cities/soka.toml

# 3. 確認待ちが出たら、Claude Code でこのリポジトリを開いて
/odkit-review

# 4. もう一度 build（判断が反映され、確認待ちが減る）
python -m odkit build cities/soka.toml
```

出力は `output/<市>/`、作業ファイル（住所検索のキャッシュ・確認リスト・判断記録）は `work/<市>/` にできます。

### 新しい市を追加する

1. `cities/soka.toml` を写して `cities/<市>.toml` を作る
2. 元データを `sources/<市>/` に置く
3. Claude Code で `/odkit-map-columns` を実行し、列の対応づけを下書きしてもらう（`python -m odkit inspect` の結果を使う）
4. 内容を確認して `build` → `/odkit-review` → `build`

## 草加市での結果

| データ | 件数 | 元データで位置があった件数 | このキットで位置が付いた件数 |
| --- | --- | --- | --- |
| AED | 108 | 0 | 108 |
| 指定緊急避難場所 | 51 | 0 | 51 |
| 公共施設 | 201 | 201 | 201 |
| 文化財 | 38 | 33（度分秒） | 38 |
| 観光施設 | 12 | 11 | 12 |

整えたデータは BODIK API で提供され、地図アプリから使われています。

## テスト

```bash
python -m unittest discover tests
```

`tests/fixtures/soka/` の草加市のデータ（元データの形式に戻したもの）で、手作業の結果（AED は公共施設からの転記 79件・住所検索 29件）が再現されること、AI の判断が検証されたうえで反映されることを確かめています。

## 現時点の課題

- 住所の分割は正規表現による簡易なもの。町字ID（アドレス・ベース・レジストリ）との結びつけは未対応
- 国土地理院の住所検索は精度の目安を返さないため、番地・街区・町字の判定は返ってきた地名との比較による推定
- 元データの更新に追従する仕組み（差分の検出・定期実行）は未実装
- BODIK などへの登録は手作業（このキットの範囲外）

詳しくは [docs/design.md](docs/design.md) を参照してください。
