# 元データの列を標準の項目に対応づける

## 手順

1. `cities/<市>.toml` がなければ、`cities/soka.toml` を写して `[city]`（slug・コード・都道府県・市名・ID の接頭辞）と各データセットの `source` を書き換える
   - 全国地方公共団体コードは、元データのファイル名（「112038_aed.csv」）や「全国地方公共団体コード」の列など、根拠を確かめてから書く。わからなければ利用者に聞く。build のときに町字マスターと照らして確かめられる
   - 市の範囲 `bbox` は `"auto"` のままにする（元データの座標から自動で決まる）。座標の数値を書かない
2. 元データを置く（`python -m odkit fetch cities/<市>.toml`、または手で `sources/<市>/` に保存）
3. `python -m odkit inspect cities/<市>.toml` を実行し、`work/<市>/inspect.json` を読む
   - `standard_columns`：書き出す標準の項目
   - `source_columns` と `samples`：元データの列名と先頭5行
   - `unmapped_source_columns`：まだどこにも使っていない元の列
4. データセットごとに対応づけを考え、toml に書く（下の規則）
5. 自信のない対応には、行末に `# 要確認：<理由>` のコメントを付ける
6. 変更点を表にまとめて利用者に見せ、承認をもらってから `python -m odkit build` を実行する

## 対応づけの規則

- `[datasets.<名前>.columns]` に `"標準の項目名" = "元の列名"` で書く
- 2つ以上の列を合わせる場合は差し込み書式：`"利用可能日時特記事項" = "利用可能日：{利用可能日}／利用可能時間：{利用可能時間}"`（空の列は見出しごと省かれる）
- 標準に当てはまる項目がない列で、捨てたくない情報は `notes` に入れる（備考欄に「列名：値」で入る）。見出しを変えたいときは `{ column = "種別", label = "施設種別" }`
- 和暦の日付の項目は `wareki = ["文化財指定日"]`、「1棟」のような数と単位は `count_split`
- 「可」「不可」「あり」のような値で書かれた災害種別などの項目は `flags = ["災害種別_地震", ...]`（「可」「あり」→1、「不可」→空欄、「2F以上」などは1にして元の値を備考へ）
- 政令指定都市は `[city.wards]` に区の名前と団体コードを書く。住所に区の名前がなく別の列にあるときは `ward_column = "区"`
- 元データがすでに標準の列名なら `passthrough = true`
- 県などの一覧から1市分を抜き出すときは `filter = { column = "所在地_連結表記", contains = "〇〇市" }`
- 1つのデータセットを複数の元データから作るときは `[[datasets.<名前>.inputs]]` を並べ、`dedupe_by_name = true`
- 緯度・経度の列が度分秒でもそのまま対応づけてよい（自動で10進数にする）
- 位置の転記元にする施設一覧（通常は公共施設）を `[reference]` に指定する。市名の接頭辞（「〇〇市立」）は `name_strip` に入れる

## してはいけないこと

- 元データにない値を作って埋めない（「該当なし」「不明」などを勝手に入れない）
- 意味が違う列を、名前が似ているだけで対応づけない（例：「設置場所_詳細」は住所ではなく `設置位置`）
- 標準の項目名を書き換えない（`standards/` の定義と完全に一致させる）
