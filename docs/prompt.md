# AI に市町村の追加を任せるプロンプト

コーディングエージェント（Claude Code など、ファイルの読み書きとコマンドの実行ができる AI）に渡す指示の例です。
`〇〇市` を対象の市町村名に、`<英字名>` を設定ファイル名に使う英字（例：`kawaguchi`）に置き換えて使います。

Claude Code でこのリポジトリを開いている場合は、`/odkit-add-city 〇〇市` と頼むだけで同じ流れになります（`.claude/skills/odkit-add-city/SKILL.md`）。

---

```text
municipal-opendata-kit（https://github.com/kt-tinker/municipal-opendata-kit）を使って、
〇〇市のオープンデータ（AED・指定緊急避難場所・公共施設・文化財・観光施設）を
デジタル庁「自治体標準オープンデータセット」の形式に整えてください。

進め方：
1. リポジトリを clone し（済みなら git pull）、CLAUDE.md、README.md、docs/design.md と、
   .claude/skills/ の odkit-add-city・odkit-map-columns・odkit-review の SKILL.md を読んでください。
   この3つのスキルの手順と「してはいけないこと」に従って作業します。
2. odkit-add-city の手順で、元データの調査 → cities/<英字名>.toml の作成 → fetch → inspect →
   列の対応づけ → build まで進めてください。
3. build で確認待ちが出たら、同じ形のものがまとまっていればキットのコードで直し（テストを足す）、
   1件ずつ事情が違うものは odkit-review の基準で判断して decisions.json に書き、もう一度 build してください。
   人の判断が要るものだけが残るまで繰り返してください。
4. 最後に、データセットごとの件数と位置の付け方の内訳、直した表記、人の確認が必要なもの（理由つき）、
   この市の元データの特徴を、表を使って日本語で報告してください。

必ず守ること：
- 緯度・経度・市の範囲の数値を自分で書かない（位置は元データ・公共施設情報・国土地理院の結果からだけ取る）
- 元データを書き換えない。標準の項目名を変えない
- work/ と output/ は git に入れない。commit はブランチまで。push や外部への送信は私に確認してから
- 迷ったら推測で埋めずに、理由を書いて人の確認に回す
- 次のときは作業を止めて私に聞く：データが PDF しかない／ライセンスがオープンでない／
  全国地方公共団体コードの根拠が見つからない／ネットワークに出られない
```

## このプロンプトで AI に任せること・任せないこと

| 工程 | 誰が | 内容 |
| --- | --- | --- |
| 元データを探す | AI（`discover`） | 県のポータルから候補を探す。県外は市のサイトを調べるか利用者に聞く |
| 設定ファイル | AI | 列の対応づけ。団体コードは元データで確かめ、build のときに町字マスターで検証される |
| 取得・整形・位置の付与 | コード | 決まった処理。AI は数値を書かない |
| 決まった形の例外 | AI がコードを直す | テストを足し、全テストが通ることが条件 |
| 1件ずつの判断 | AI（`odkit-review`） | 根拠つきで decisions.json に書く。コードが検証し、通らなければ差し戻す |
| 市への確認事項 | 人 | AI が `needs_human` にしたもの |
| 公開（push・登録） | 人 | AI は commit まで |
